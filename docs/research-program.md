# Research Program

## Purpose

Technocommunistic COBOL Terminal is an experimental research laboratory for deterministic economic protocols.

The research program studies how finance, economics, mathematics, graph theory, mechanism design, and software engineering can be combined into inspectable rules for economic claims and distribution.

The executable economic engine inside the project is the Distribution Machine.

## Research Question

Can economic contribution and distribution inside an organization be represented by rules that are:

- deterministic
- inspectable
- reproducible
- evidence-backed
- challengeable
- resistant to gaming
- versioned over time

## Research Boundary

This project does not treat AI output as authoritative economic evidence.

AI may assist with discovery, explanation, or provenance suggestions, but economic claims must be derivable from deterministic rules and inspectable evidence.

Current research software is not production compensation policy, payroll, accounting advice, or an investment product.

## Core Economic Separation

Capital != Labor != Contribution != Stewardship

These claim classes may terminate at the same person, but they must remain economically distinct.

Labor is a contractual obligation.

Capital is a bounded financial claim.

Contribution represents evidence-backed creation of durable capability.

Stewardship represents responsibility for preserving valuable systems through time.

## Measurement Chain

REAL WORLD
-> EVIDENCE
-> OBSERVABLES
-> MEASUREMENT FUNCTION
-> NORMALIZED PARAMETER
-> CLAIM
-> ALLOCATION
-> MONEY

No scored parameter without a measurement function.

No measurement without observable evidence.

## Research Method

Hypothesis
-> Formula
-> Executable Invariant
-> Pathological Test
-> Observation
-> Finding
-> Protocol Correction

A failing pathological test can be successful research evidence.

The purpose of adversarial tests is to discover semantic failure before real money depends on the rule.

## Current Adversarial Themes

Current experiments include founder gravity, invisible infrastructure, activity farming, weak-signal accumulation, threshold cliffs, duplicate edges, structural identity laundering, path laundering, shared bottlenecks, and failure-domain laundering.

One current research conclusion is:

INDEPENDENCE IS A PROPERTY OF GRAPH STRUCTURE, NOT OF LABELS.

The next measurement stage will test graph-derived structural independence instead of trusting declared identifiers.

## Protocol Versioning

Historical calculations must remain reproducible.

Evidence + Measurement Rules + Protocol Version = Reproducible Allocation

Experimental protocol parameters are hypotheses until promoted through evidence, testing, and explicit governance.

## Research Deliverables

The laboratory should produce:

- executable protocol code
- invariants
- pathological tests
- findings
- synthetic simulations
- measurement specifications
- provenance rules
- economic statements
- worker-facing explanations
- Ratatui instrumentation

## Terminal End State

The intended interface is an old-school Rust terminal built with Ratatui.

Its job is to make protocol state inspectable.

A future operator should be able to inspect pools, claims, measurements, evidence, simulations, protocol diffs, pathological-test status, and the derivation of any allocation.

The canonical diagnostic question is:

WHY THIS AMOUNT?

The terminal should answer by tracing money backward through allocation, claim, measurement, observables, and evidence.

## Standard of Evidence

A protocol rule is not accepted because it sounds fair.

It must survive executable examples, counterexamples, provenance inspection, and adversarial tests.

If the implementation disproves the theory, the theory changes.
